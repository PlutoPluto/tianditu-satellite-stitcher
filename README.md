# 天地图卫星影像 下载拼接（静态版）

> 单文件、纯前端的天地图卫星瓦片下载与拼接工具。浏览器直连天地图拉取瓦片、在本地 Canvas 拼接成一张完整 JPEG 并保存到本机 —— 没有服务器参与下载，没有后端代码，Token 不出你的浏览器。

**在线使用**：<https://plutopluto.github.io/tianditu-satellite-stitcher/>
**本地使用**：下载 `index.html`，双击用浏览器打开（`file://` 亦可，无需起服务）

## 为什么有这个工具

要一张某片区域的高清卫星图，通常会写个 Python 脚本拉瓦片再用 PIL 拼。但那套东西需要 Python 环境、依赖安装、命令行操作，别人想用一次就得先配环境。

本工具把同一套逻辑搬进了浏览器：

| | 传统 Python + PIL 脚本 | 本工具（静态版） |
| --- | --- | --- |
| 运行环境 | Python 3 + requests + Pillow | 任意现代浏览器 |
| 部署 | 需服务器 / 本地跑脚本 | 一个 HTML 文件，静态托管即可 |
| 选范围 | 手填四角经纬度 | 地图上拖框选取，所见即所得 |
| 进度反馈 | 命令行输出 | 进度条 + 重试轮次 + 退避倒计时 |
| 数据流向 | 服务器中转下载 | 浏览器直连天地图，不经过任何中间服务器 |
| 输出一致性 | — | c 瓦片 + 逐行拉伸，与 PIL 后端结果一致 |

适用于：工程前期踏勘底图、汇报用示意图、地块周边影像留档等"要一张图但不想配环境"的场景。

## 快速开始

1. 打开页面（在线地址或本地 `index.html`）
2. 首次进入会弹出 Token 输入框 —— 填入你的天地图 Token
   （在 [天地图开放平台控制台](https://lbs.tianditu.gov.cn/authorize/authorization.html) 申请，类型选**浏览器端**），回车或点「进入」
3. 拖动地图到目标区域，设置 zoom 级别
4. 点左侧「**✥ 框选范围**」，在地图上按住左键拖动画框，松开即确定
   （也可以不点按钮，直接在地图上点两个对角点）
5. 看「任务预估」确认瓦片数与输出尺寸没问题，点「**开始下载并拼接**」
6. 完成后预览图出现，点「下载完整 JPG」保存到本地

Token 会存进 `localStorage`，下次打开直接进入地图；在侧栏 Token 框里换一个再点「使用」，页面会自动重载并重建地图图层。

## 两个关键设计

### 1. 显示用 `w` 剖分，下载用 `c` 剖分

这是本工具最容易被忽略、但最要紧的一点：

| | 显示（地图浏览） | 下载（出图） |
| --- | --- | --- |
| 图层 | `img_w` / `cia_w` | `img_c` / `cia_c` |
| TILEMATRIXSET | `w` | `c` |
| 投影 | Web 墨卡托（EPSG:3857） | 等经纬（EPSG:4490） |
| 网格 | 全球正方形网格，自洽 | 经纬度等分网格 |
| 为什么 | 任意位置的横向/纵向屏幕比例与实地一致，高纬度不被压扁，拖框选范围时"看到的形状就是地面的形状" | 与原始 Python 后端、既有出图规范一致，且行列号有闭式公式、逐行拉伸规则明确 |

地图瓦片必须用 `w`，否则高纬度地区在屏幕上会被严重压扁，用户框出来的范围在视觉上是错的。而下载沿用 `c` 是为了与已有的后端流程和出图口径对齐。两者以**经纬度**为桥梁：你在 `w` 地图上框出的 `[lonMin, lonMax] × [latMin, latMax]`，直接用于计算 `c` 瓦片的行列号。

### 2. 逐行按 `cos(纬度)` 拉伸

`c` 瓦片每块覆盖 `360/2^z` 度经纬、恒为 256×256 像素。若直接 256 像素铺贴，图像在纵向会被压扁（因为同样度数，高纬度的地面实际距离更短）。

所以拼接时**逐行取拉伸系数**：

```
第 r 行像素高度 = floor( 256 / max(|cos(lat_r)|, 1e-6) )，  lat_r = 90 − 360·r/2^z
```

效果是每一行内横纵像素代表的**地面距离相等**（各向同性），图像看起来不失真。这个做法等价于对墨卡托纵向伸展做**分段常数近似** —— zoom 越高、行越细，越逼近标准 Web 墨卡托。

> 推论：输出图的宽高比**不等于**你框选矩形的宽高比，上下会被拉长，这是正常的。也正因如此，把输出图丢进 GIS 直接按 EPSG:3857 配准会有亚行级偏差，需要精确配准时建议用四角坐标做仿射或多项式纠正。

## 计算规则

### 经纬度 → 瓦片行列号

```
n   = 2^zoom
col = floor( (lon + 180) / 360 · n )
row = floor( (90 − lat)  / 360 · n )
```

选区的左上角取 `(lonMin, latMax)`、右下角取 `(lonMax, latMin)`，得到 `cMin/cMax/rMin/rMax`，瓦片数 = `rows × cols`。

### 输出尺寸

```
width  = cols × 256
height = Σ_{r=rMin..rMax} floor( 256 / max(|cos(lat_r)|, 1e-6) )
```

预估面板与最终 Canvas 用同一套公式，所以预估尺寸就是实际尺寸。

### 输出四角坐标

结果表的角点用**瓦片边界**而非选区边界：

```
lonL = cMin / n · 360 − 180
lonR = (cMax + 1) / n · 360 − 180
latT = 90 − 360 · rMin / n
latB = 90 − 360 · (rMax + 1) / n
```

因为瓦片只能整块取，输出范围通常会比选区**略大**（最多外扩不到一块瓦片）。表中给的就是这张图真正对应的范围，写报告时用这个值。

坐标一律按 **WGS84** 输出，不做 CGCS2000 转换。

## 下载引擎

页面只做一件事：`fetch` 一堆瓦片 → `createImageBitmap` → 画进 Canvas。难点全在"网络不稳时怎么把瓦片凑齐"。

```
预估 → 生成任务队列 [col, row, layer] → 并发池(8) 拉取
                ↓ 失败进入下一轮
     轮间退避 1–5s（带倒计时）→ 换子域重试 → 最多 10 轮
                ↓
        拼接（逐行拉伸 + 注记叠加）→ toBlob(JPEG, 0.95) → 下载
```

| 机制 | 实现 | 目的 |
| --- | --- | --- |
| 并发 | 8 个 runner 共抢一个任务游标 | 兼顾速度与浏览器连接数上限，不打爆天地图 |
| 单请求超时 | `AbortController` + 20 s | 挂死的请求不会拖住整轮 |
| 子域轮换 | 首选用 `(col+row) % 8`，重试时偏移 `+3`、`+6` 换节点 | 分散到 t0–t7，绕过单个节点限流 |
| 单片重试 | 每轮内最多 3 次 | 瞬时抖动在轮内解决 |
| 整体重试 | 失败瓦片重新入队，最多 10 轮 | 应对成片失败（限流、短时断网） |
| 轮间退避 | `1 × min(round, 5)` 秒，逐秒倒计时 | 给服务端喘息，避免越重试越被限 |
| 防缓存 | `cache: 'no-store'` + URL 追加 `&_cb=<时间戳>-<attempt>` | 关键：否则失败响应被浏览器/代理缓存，重试轮会"命中缓存空转"，网络面板看不到新请求，白等 10 轮 |
| 内容校验 | `content-type` 以 `image/` 开头 且 `blob.size > 100`（`img`）/ `> 40`（`cia`） | 天地图出错时会返回 200 + JSON/HTML，必须按内容判断而非只看状态码；`cia` 的空瓦片是极小透明 PNG，阈值单独放宽 |
| 解码 | `createImageBitmap(blob)` | 异步解码，不阻塞主线程，比 `new Image()` 快 |

单个瓦片最坏情况请求次数 = 3 次/轮 × 10 轮 = **30 次**，全部走完才判定为失败。

## 失败处理策略

十轮重试后仍有瓦片没下来时，**不取消任务**，而是降级出图：

- Canvas 先铺**白底**（`#ffffff`），成功瓦片逐块覆盖上去，失败位置自然留白；
- 影像瓦片失败 → 该处白色；
- 注记瓦片失败 → 该处只是没有注记，底图完好（注记是独立透明图层，缺了不影响影像）；
- 侧栏红色提示条给出明细：`提示：N 块影像瓦片（白色填充）、M 块注记瓦片（该处无注记）在 K 轮重试（累计请求 X 次）后下载失败，已继续拼接。`
- 结果卡片里「失败瓦片」一栏同样列出 `失败数 / 总数`。

这样做的判断是：**一张缺了几块的图，比一张什么都没出来的图有用**。缺块位置一目了然（纯白），也不会被误认为"下载成功了"。

进度条在不同阶段的表现：

| 阶段 | 显示 |
| --- | --- |
| 第一轮下载 | 全局进度 `下载瓦片中 128/256`，百分比为全局 |
| 进入重试 | 进度条**从 0 重新涨**，文案 `第 2 轮重试中 12/34（共 34 块待重下，已请求 296 次）` |
| 退避等待 | `第 2 轮重试：3s 后重新下载（34 块待重下，已请求 296 次）` |
| 拼接 | `拼接处理中` / `拼接处理中（含失败瓦片留白）` |

重试轮特意重置进度条，是为了让用户看出"还在干活"，而不是盯着一个不动的 99% 以为卡死了。

## 影像注记叠加

地图右上角勾选「叠加影像注记 (cia)」，任务开始时会**同时下载一套 `cia_c` 透明 PNG 瓦片**，在影像之上逐块叠加绘制：

- 任务数翻倍（预估面板的瓦片总数是影像数，勾选后实际任务数是它的两倍）；
- 注记瓦片与影像瓦片共用同一行列号、同一目标矩形，按行高一起拉伸，所以位置天然对齐；
- 空瓦片（大片区域没有地名标注）是非常小的透明 PNG，用 `> 40 B` 的尺寸下限过滤，不会当成失败反复重试；
- 注记瓦片下载失败时只是该块无注记，不触发留白。

注意：勾选状态在**点开始时**读取，下载途中改勾选不影响本次任务。

## 可调参数速查

全部集中在 `index.html` 的「常量与状态」区（约第 880 行起），改完刷新即生效：

| 常量 | 默认 | 含义 | 调大的后果 |
| --- | --- | --- | --- |
| `TILE_FETCH_CONCURRENCY` | `8` | 并发的瓦片连接数 | 更快，但更容易触发限流 |
| `TILE_RETRIES` | `3` | 单块瓦片单轮内的尝试次数 | 更耐抖动，单轮更慢 |
| `TILE_RETRY_ROUNDS` | `10` | 整体重试轮数上限 | 更耐长时间故障，最坏耗时线性增长 |
| `TILE_TIMEOUT_MS` | `20000` | 单请求超时（ms） | 弱网下更少误杀，但也更慢放弃 |
| `CANVAS_MAX_SIDE` | `16000` | Canvas 单边像素上限 | 别动，这是浏览器硬限制 |
| `CLICK_THRESHOLD_PX` | `5` | 拖动多少像素才算画框（否则算单击选点） | 调大更不容易误触发框选 |

其他可改点：`TOKEN_KEY`（localStorage 键名）、初始中心与 zoom（`initMap` 里 `center` / `zoom`）、`minZoom` / `maxZoom`。

## 常见问题

**Q：框选按钮点了，但在地图上拖不出框？**
A：确认已点「✥ 框选范围」（按钮会变成「✕ 取消框选」，鼠标变十字准星，顶部提示变"框选模式"）。框选模式下地图拖动被临时禁用，左键拖动画框；选定后自动切回平移模式。松开鼠标时若在画框，那次点击不会再额外落一个对角点。

**Q：不点按钮，直接点两下能不能选？**
A：可以。点两个对角点会生成编号 ①② 的标记并确定范围；点第三下会清空重来。拖动距离小于 5 px 才算"点击"，所以轻微手抖不会误判。

**Q：下载的图比框的范围大一圈？**
A：瓦片只能整块取。选区边界会向外对齐到最近的瓦片边界，最多外扩不到一块瓦片。真实范围以结果卡片里的四角经纬度为准。

**Q：输出图的宽高比和选区不一致？**
A：正常。逐行按 `cos(纬度)` 拉伸，上下方向被拉长了，目的是让像素在各方向代表的地面距离相等。

**Q：Token 明明填了，地图却一片灰 / 瓦片 403？**
A：三个常见原因 —— ① Key 类型不是"浏览器端"；② 控制台里给这个 Key 配了域名白名单，当前页面的域名（如 `plutopluto.github.io` 或 `file://`）不在其中；③ 当日配额用尽。改完配置后回侧栏重新点一次「使用」会重载页面。

**Q：进度条 99% 卡住？**
A：已经进入重试轮了，看文案里的"第 N 轮重试"和倒计时。若长时间不动，多半是本机网络到天地图不稳定，或选区太大导致失败瓦片多、轮数走满。

**Q：可以只要注记、不要影像吗？**
A：目前不支持。注记是叠加层，必须依附影像输出。

**Q：能导出带地理坐标的 GeoTIFF 吗？**
A：不能，纯前端只出 JPEG。四角经纬度已给全，需要时在 GIS 里手动配准。

## 限制

- **Canvas 单边 ≤ 16000 px**：浏览器画布硬限制。超出时预估面板会警告并禁用开始按钮，请缩小范围或降低 zoom。注意是**单边**，不是面积 —— 16000×16000 在多数机器上已经接近内存红线。
- **Token 需自备**：本工具不内置、不代理任何 Token。天地图对免费 Key 有日配额，大范围高 zoom 任务很容易吃掉配额。
- **内存与稳定性**：整张图在内存里拼完之后才编码，瓦片数上万时可能因内存不足导致 `toBlob` 返回 null（届时会提示"图像编码失败"）。
- **网络可达性**：瓦片下载直接取决于你本机能访问 `t0–t7.tianditu.gov.cn`。某些企业网络/代理会拦掉部分子域，表现为成片失败。
- **单点精度**：`cos` 拉伸用行上边界纬度取样，与严格墨卡托有亚行级差异（zoom 越低越明显）。用于底图与示意足够，用于精密量测请重新配准。
- **无移动端适配**：侧栏固定 392 px 宽，界面按桌面端设计，手机/平板上体验较差。
